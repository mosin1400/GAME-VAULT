# ایجنت ساخت اتوماسیون Codex

## تنظیم اتصال

اتصال فقط در سمت سرور انجام می‌شود. مقادیر را در `.env` همین پوشه قرار دهید:

```dotenv
CODEX_ACCESS_TOKEN=
CODEX_ACCOUNT_ID=
CODEX_MODEL=gpt-5-codex
CODEX_BASE_URL=https://chatgpt.com/backend-api/codex
```

توکن و شناسه حساب باید متعلق به حساب مجاز خودتان باشند. توکن را در چت ایجنت یا JSON جریان قرار ندهید. اگر از endpoint رسمی Responses API با API Key استفاده می‌کنید، آدرس را به `https://api.openai.com/v1` تغییر دهید و کلید همان endpoint را در `CODEX_ACCESS_TOKEN` قرار دهید. مدل باید در حساب/endpoint شما قابل دسترسی باشد. برنامه بعد از تغییر `.env` باید مجدداً اجرا شود.

آدرس backend اشتراک Codex ممکن است تغییر کند؛ این اتصال تا واردکردن توکن واقعی آزمایش نشده است. ورود و تمدید خودکار توکن پیاده نشده؛ توکن منقضی‌شده را خودتان جایگزین کنید. خواندن پاسخ JSON و SSE مطابق رویدادهای Responses انجام می‌شود: https://openai.com/index/unrolling-the-codex-agent-loop/ و https://platform.openai.com/docs/api-reference/responses-streaming

## استفاده

۱. وارد برنامه شوید و Credential سرویس‌های مقصد را از صفحه اعتبارنامه‌ها بسازید.
۲. در «جریان‌های کاری»، «ساخت با AI» را باز کنید.
۳. درخواست شامل تریگر، آدرس API، شرط و مقصد خروجی را توضیح دهید.
۴. ایجنت ابزارها را جستجو و schema و نکات اجرایی آن‌ها را می‌خواند. اگر اطلاعات کافی نباشد سؤال می‌پرسد؛ پاسخ را در همان کادر ارسال کنید.
۵. نام، نودها، هشدارها، نیازمندی‌ها و JSON پیش‌نویس را بررسی کنید. با درخواست بعدی می‌توانید آن را اصلاح کنید.
۶. «ذخیره پیش‌نویس و بازکردن ویرایشگر» جریان غیرفعال می‌سازد. ذخیره به معنای اجرا، ارسال پیام یا فعال‌کردن زمان‌بندی نیست.
۷. Credentialها، کد و تنظیمات را در ویرایشگر بررسی کنید؛ سپس خودتان تست و فعال کنید.

## قرارداد API

`POST /api/ai/build` نیاز به session معتبر و نقش owner/admin/editor/member دارد:

```json
{"prompt":"هر روز API خودم را بخوان و نتیجه را ارسال کن","history":[{"role":"user","content":"درخواست قبلی"},{"role":"assistant","content":"سؤال قبلی"}]}
```

پاسخ `status=clarification` شامل message/questions است. پاسخ `status=draft` شامل name/nodes/edges/explanation/requirements/warnings/trace است و در این مرحله چیزی در دیتابیس ذخیره نمی‌شود.

محدودیت‌ها: حداکثر ۱۰ مرحله مدل، ۶۰ نود، ۱۲۰ اتصال، ۱۲۰۰۰ کاراکتر درخواست، یک درخواست همزمان برای هر کاربر در هر فرآیند و timeout چهار دقیقه. تاریخچه در مرورگر نگهداری می‌شود و بعد از refresh از بین می‌رود.

## بررسی ابزارها

ابزارهایی با handler ناموجود، noop، NODES_EXCLUDE و shell غیرفعال به ایجنت ارائه نمی‌شوند. نوع و پارامتر نود، enumها، شناسه‌ها، Credential، شاخه‌ها، ورودی‌ها، مسیر دسترسی و چرخه‌ها بررسی می‌شوند. Integration عمومی به endpoint واقعی نیاز دارد؛ انتخاب operation به‌تنهایی پیاده‌سازی اختصاصی آن سرویس نیست. بعضی تریگرهای کاتالوگ هنوز به دریافت رویداد واقعی وصل نیستند؛ هشدار بررسی جداگانه دارند. اعتبارسنجی ساختار، درستی کسب‌وکار یا دسترسی واقعی به سرویس را تضمین نمی‌کند.

نام، نوع و شناسه Credential به مدل داده می‌شود؛ مقدار آن رمزگشایی یا ارسال نمی‌شود. Agent هیچ ابزار اجرای shell، workflow یا درخواست خارجی برای انجام عملیات کاربر ندارد؛ ابزارهایش جستجو، خواندن مشخصات و تولید پیش‌نویس جریان یا کد نود هستند.

## تولید نود جدید با کد

با حساب owner/admin درخواست کنید: «یک نود custom.multiply بساز که پارامتر عددی factor با مقدار پیش‌فرض ۳ داشته باشد، value هر آیتم را ضرب کند و در شاخه main خروجی بدهد؛ سپس آن را در اتوماسیون من استفاده کن.»

ایجنت ابتدا کاتالوگ واقعی را بررسی می‌کند. اگر ابزار موجود کافی نباشد، می‌تواند action=create_node پیشنهاد دهد. پاسخ status=node_draft شامل spec و trace است؛ هنوز چیزی نصب یا اجرا نمی‌شود. در پنجره AI نام، پارامترها، شاخه‌ها و کد را ببینید، JSON را دانلود کنید و فقط پس از بررسی کد، تیک تأیید و دکمه نصب را بزنید. سپس درخواست ادامه ساخت جریان را ارسال کنید تا ایجنت نود نصب‌شده را دوباره از کاتالوگ بخواند.

نود نصب‌شده بلافاصله در کاتالوگ و ویرایشگر قابل انتخاب است. کد آن در جدول customNodes ذخیره و از طریق executor واقعی اجرا می‌شود؛ ایجنت فایل‌های اصلی پروژه را خودسرانه بازنویسی نمی‌کند. این نسخه نود پردازشی JavaScript با یک یا دو ورودی می‌سازد، نه تریگر شنونده جدید یا بسته npm. نصب بسته یا دانلودی برای تولید هر نود انجام نمی‌شود.

کد async به `$items`، `$params`، `$credential` و `$vars` دسترسی دارد. خروجی باید شیئی از شاخه‌های اعلام‌شده و آرایه آیتم‌های `{json:{...}}` باشد. پارامترهای expression بر اساس آیتم اول حل می‌شوند. Credential انتخاب‌شده فقط هنگام اجرای جریان به کد داده می‌شود، نه به مدل. کلیدها را در سورس نود قرار ندهید.

اجرای کد در فرآیند فرزند، با timeout پیش‌فرض ۱۵ ثانیه و سقف ۳۰ ثانیه، محدودیت JSON یک مگابایت و حداکثر ۱۰۰۰ آیتم در هر شاخه انجام می‌شود. این فرآیند **sandbox امنیتی نیست**؛ کد تأییدشده ممکن است به فایل‌ها و شبکه با دسترسی کاربرِ برنامه دسترسی پیدا کند. فقط کد قابل‌اعتماد نصب کنید. بررسی syntax و ساختار، صحت عملکرد یا بی‌خطر بودن کد را تضمین نمی‌کند.

`POST /api/nodes/custom` با `{spec,confirmCode:true}` برای owner/admin نود را نصب می‌کند. نوع باید با custom. شروع شود؛ بازنویسی نود موجود، نام‌های رزروشده، پارامتر کلید مخفی و شاخه تکراری رد می‌شوند. حذف با `DELETE /api/nodes/custom?type=custom.multiply` فقط اگر جریان ذخیره‌شده‌ای از نود استفاده نکند ممکن است. کاتالوگ عمومی سورس کد را برنمی‌گرداند.

## دیدن ظاهر و تست واقعی

فایل `visual-preview.html` در ریشه پروژه را دوبار کلیک کنید. بدون اینترنت، دیتابیس و نصب باز می‌شود. «تست نمایشی» برای value=4 و factor=3 خروجی 12 نشان می‌دهد و پنجره بازبینی کد نیز قابل مشاهده است. این فایل صرفاً نمایش مستقل ظاهر و تعامل پیشنهادی است؛ تست رابط واقعی Next.js یا اتصال Codex نیست.

برای برنامه واقعی، پس از نصب یک‌باره وابستگی‌ها طبق فایل نصب ویندوز/لینوکس و روشن کردن PostgreSQL، در پوشه پروژه اجرا کنید:

```powershell
# Windows: فقط پس از نصب وابستگی‌های پروژه
npx.cmd --no-install drizzle-kit push --force
npm.cmd run dev
```

```bash
# Linux: فقط پس از نصب وابستگی‌های پروژه
npx --no-install drizzle-kit push --force
npm run dev
```

Schema جدید باید پیش از اجرای برنامه اعمال شود؛ روی دیتابیس دارای اطلاعات ابتدا backup بگیرید و تغییرات schema را بررسی کنید. سپس http://localhost:3000 را باز کنید، وارد شوید و در جریان‌های کاری «ساخت با AI» را انتخاب کنید. برای تست واقعی تولید نود، توکن معتبر را در .env قرار دهید، درخواست نمونه بالا را ارسال کنید، کد را بررسی و نصب کنید و یک جریان Manual → custom.multiply با value=4 و factor=3 اجرا کنید. خروجی مورد انتظار value=12 است. نصب و بازبینی نود به معنای اجرای خودکار آن نیست.

## تست آفلاین بدون دانلود

با Node 22.18+ یا 24:

```bash
node --experimental-loader ./tests/agent-loader.mjs --test ./tests/agent.test.mjs
```

این تست‌ها از مدل پاسخ مصنوعی می‌گیرند و روی کاتالوگ واقعی اجرا می‌شوند؛ هیچ کلید، دانلود یا تماس خارجی لازم ندارند. build کامل Next.js و تست اتصال حساب واقعی بعد از نصب یک‌باره dependencyها و تنظیم توکن انجام می‌شود.
