# طراحی خروجی‌های نصب‌شدنی بازی

## هدف

هر نسخه از یک بازی HTML بتواند از پنل مدیریت به خروجی‌های واقعی قابل نصب تبدیل شود: Windows EXE و ZIP، Linux AppImage و tar.gz، و Android APK. خروجی‌ها باید به همان بازی و همان نسخه متصل بمانند و از کارت بازی قابل دانلود باشند.

## تجربه کاربری

- در مدیریت هر بازی، دکمه «ساخت خروجی نصب» بازکننده پنل ساخت است.
- کاربر پلتفرم‌ها را انتخاب می‌کند: Windows، Linux و Android.
- پیش از اولین ساخت، سیستم ابزارهای لازم را بررسی می‌کند.
- ابزار گمشده با نام، علت، حجم تقریبی و دکمه «نصب با تأیید من» نمایش داده می‌شود. بدون این تأیید هیچ دانلود یا نصبی انجام نمی‌شود.
- پس از آماده‌بودن ابزارها، یک Job برای همان بازی و نسخه ساخته می‌شود؛ پنل وضعیت صف، مرحله جاری، خروجی زنده و خطا را نمایش می‌دهد.
- پس از موفقیت، خروجی‌ها در منوی دانلود کارت بازی به تفکیک پلتفرم و فرمت ظاهر می‌شوند.

## معماری ساخت

- Windows: Electron Builder، با ورودی `games/<slug>/versions/<version>/`، خروجی `Setup.exe` و ZIP.
- Linux: Electron Builder، خروجی AppImage و tar.gz. اجرای ساخت روی Windows به WSL یا Docker نیاز دارد؛ اگر موجود نبود، ابتدا همان ابزار به کاربر پیشنهاد می‌شود.
- Android: Capacitor Android، با ورودی همان بازی HTML، خروجی APK. Android SDK و Java باید روی سیستم نصب باشند.
- بسته‌ها در `builds/<slug>/<version>/<platform>/` ذخیره می‌شوند و هر Job فایل گزارش مستقل دارد.

## مدیریت وابستگی‌ها

- Node.js و npm پیش‌نیاز مشترک هستند.
- Windows: Electron و electron-builder از وابستگی‌های پروژه نصب می‌شوند.
- Linux: علاوه بر Electron Builder، WSL یا Docker لازم است.
- Android: Java LTS، Android SDK command-line tools، platform-tools و build-tools لازم است.
- حجم‌ها از ابزار نصب‌کننده یا metadata رسمی خوانده می‌شوند؛ اگر اندازه دقیق در دسترس نبود، «تقریبی» برچسب می‌خورد.
- نصب ابزارها فقط از command رسمی پلتفرم و تنها پس از POST تأییدشده از رابط کاربری اجرا می‌شود.

## ایمنی و خطا

- هیچ فرمان نصب یا build از متن آزاد کاربر ساخته نمی‌شود؛ فقط شناسه‌های ازپیش‌تعریف‌شده ابزار پذیرفته‌اند.
- هر Job فقط زیر پوشه همان نسخه اجرا می‌شود.
- خروجی‌های ناموفق دانلودشدنی نمی‌شوند و لاگ خطا قابل مشاهده است.
- حذف بازی یا نسخه، پوشه خروجی‌های همان مورد را نیز با تأیید جداگانه پاک می‌کند.

## آزمون پذیرش

- بررسی ابزارها بدون تغییر سیستم انجام شود.
- نصب تنها پس از تأیید صریح UI شروع شود.
- یک بازی نمونه برای Windows به EXE و ZIP ساخته و قابل دانلود شود.
- در نبود Android SDK، UI ابزارها و حجم‌ها را نشان دهد و APK را تا تکمیل نصب در وضعیت آماده‌سازی نگه دارد.
- ساخت Linux بدون WSL/Docker با خطای عملی و راهنمای نصب خاتمه یابد.
- خروجی هر نسخه فقط به همان بازی و نسخه وابسته باشد.
