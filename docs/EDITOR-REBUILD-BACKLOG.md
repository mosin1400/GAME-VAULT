# فهرست اجرای بازسازی Game Vault Studio

این سند مرجع اجرای مرحله‌ای است. موارد مربوط به ادیتور HTML قدیمی که دیگر مبنای کار نیستند، از این فهرست حذف شده‌اند. مبنا فقط ادیتور مستقل Theia است.

## اصل‌های غیرقابل‌مذاکره

- هیچ پروژهٔ خارج از `games/<slug>/versions/<version>/` نباید در Studio بازی باز شود.
- هر نسخه یک پوشه و مجموعه‌فایل مستقل است؛ فایل نسخه‌ها هرگز با هم مخلوط نمی‌شود.
- `game.json` و `README.md` فایل‌های اصلی نسخه‌اند و از طریق فرم گرافیکی مدیریت می‌شوند.
- کنترل نسخه فقط در نوار بالایی، سمت راستِ ادیتور قرار دارد و نام نسخه را از `game.json.version` می‌خواند.
- چت، پیش‌نمایش، کنترل نسخه و تم، اجزای Native Theia هستند؛ هیچ Overlay شناور جداگانه‌ای مجاز نیست.
- تم روشن و تاریک فقط از تم‌های اصلی Theia استفاده می‌کند، نه رنگ‌گذاری سفارشی روی صفحه.

## مرحلهٔ پیش‌نیاز — بازآرایی ایمن فایل‌ها و کد

- [ ] ساختار کل پروژه بازبینی و به پوشه‌های روشنِ `server`، `frontend`، `theia`، `shared`، `tests` و `docs` تفکیک شود؛ فایل‌های نامرتبط و تکراری حذف یا ادغام شوند.
- [ ] فایل‌های CSS تک‌خطی به فایل‌های خوانا، بخش‌بندی‌شده و دارای tokenهای مشترک تبدیل شوند.
- [ ] کدهای JavaScript/Node بزرگ به ماژول‌های کوچک با مسئولیت مشخص تقسیم شوند.
- [ ] ظاهر، مسیرها، APIهای موجود و رفتار کاربر نباید در این مرحله تغییر کند.
- [ ] برای هر جابه‌جایی، تست یا قرارداد محافظ وجود داشته باشد تا صفحه‌ها، APIها و مسیرهای بازی خراب نشوند.
- [ ] `.env` و اطلاعات محرمانه هرگز خوانده، منتقل یا وارد Git نمی‌شوند.
- [ ] پس از بازآرایی، فقط تکرارها و کد مردهٔ اثبات‌شده حذف می‌شود؛ هیچ قابلیت فعالی حذف نمی‌شود.

## مرحلهٔ 0 — پایداری ورود و محدودهٔ Workspace

- [ ] نشست کاربری برنامه و Theia یکپارچه شود؛ مدیرِ واردشده در مدیریت بازی، در Agent نیز مدیر شناخته شود.
- [ ] خطای نادرست «باید با حالت مدیر وارد شوید» برای پروژه‌ای که از پنل مدیریت باز شده رفع شود.
- [ ] هنگام ورود به Studio، Workspace دقیقاً از URL پروژه و نسخهٔ انتخاب‌شده ساخته شود.
- [ ] با خروج از یک پروژه یا رفتن به پوشهٔ دیگر، فایل/Workspace قبلی به پروژهٔ بعدی نشت نکند.
- [ ] حالت عادی Studio فقط Workspace بازی انتخاب‌شده را ببیند و هیچ فایل خارجی را باز نکند.
- [ ] دکمهٔ «باز کردن استادیو آزاد» در داشبورد مدیریت اضافه شود؛ فقط در این حالت اجازهٔ انتخاب و ویرایش فایل‌های آزاد داده شود.
- [ ] بازگشت از Studio به «داشبورد ویرایش» انجام شود، نه صفحهٔ نامرتبط.

## مرحلهٔ 1 — منو و نوار بالای Studio

منوی File باید فقط این عمل‌ها را داشته باشد:

- [ ] نگه‌دار: `New Text File`، `New File`، `Save`، `Save All`، `Save As`، `Auto Save`، `Upload Files`، `Preferences`، `Close Editor`.
- [ ] حذف: `New Window`، `Open...`، `Open Workspace from File`، `Open Recent Workspace`، `Close Workspace`.
- [ ] `Close Editor` به داشبورد ویرایش Game Vault برگردد.
- [ ] انتخاب نسخه در نوار بالای سمت راست اضافه/تکمیل شود؛ تغییر آن فقط Workspace همان نسخه را باز کند.
- [ ] دکمهٔ پیش‌نمایش بازی در نوار بالای سمت راست قرار گیرد.
- [ ] نوار کنترل چیدمان پنل‌ها، با الهام از تصویر مرجع کاربر، اضافه شود: نمایش/پنهان‌سازی Explorer، پنل پایین و پنل راست، با آیکون‌های خوانا.

## مرحلهٔ 2 — متادیتا و فایل‌های اصلی نسخه

- [ ] اگر `game.json` یا `README.md` وجود ندارد، در صفحهٔ گرافیکی متادیتا دکمهٔ «ایجاد فایل‌های اصلی» نمایش داده شود.
- [ ] دکمه، هر دو فایل را با قالب معتبر و داده‌های قابل‌بازیابی بسازد.
- [ ] اگر JSON نامعتبر، کلیدهای اجباری ناقص، یا README خارج از قالب بود، فرم گرافیکی خطا را واضح نشان دهد.
- [ ] دکمهٔ «تصحیح قالب» در همان فرم گرافیکی، فقط قالب و کلیدهای الزامی را اصلاح کند و دادهٔ موجود را حفظ کند.
- [ ] تغییر `version` در فرم، همان لحظه کنترل نسخهٔ بالای ادیتور و نام پوشهٔ نسخه را همگام کند.
- [ ] کلیک روی `game.json` یا `README.md` صفحهٔ گرافیکی متادیتا را باز کند، نه Text Editor.
- [ ] `README.md` از داده‌های واقعی `game.json` تولید/همگام شود و در صفحهٔ جزئیات عمومی بازی واقعاً نمایش داده شود.
- [ ] حذف یا تغییرنام این دو فایل ممنوع بماند.

## مرحلهٔ 3 — هستهٔ واقعی VS Code Web

- [ ] پشتیبانی واقعی زبان‌های HTML، CSS، JavaScript، JSON و Markdown برای Monaco/Theia فعال شود.
- [ ] رنگ‌بندی Syntax، آیکون فایل و زبان انتخاب‌شده با تم اصلی Theia هماهنگ باشد.
- [ ] تشخیص خطای HTML/CSS/JS/JSON اجرا شود؛ هر خطا یک ردیف مستقل در Problems داشته باشد.
- [ ] خطاها در متن با underline قرمز و پیام Hover دیده شوند.
- [ ] کلیک Problems یا خط قرمز، همان فایل و همان خط را باز کند.
- [ ] فایل خالی و فایل بلند بدون بیرون‌زدن از صفحه یا شکستن Layout باز شود.
- [ ] پیش‌نمایش امن تصویر، ویدئو و صوت برای فایل‌های رسانه‌ای اضافه شود.
- [ ] تنظیمات Theme، Font، Font Size، Word Wrap و Auto Save در Preferences پایدار ذخیره شود.

## مرحلهٔ 4 — Agent داخلی و اصلاح AI

- [ ] فقط یک پنل چت Native Theia وجود داشته باشد؛ هیچ پنل Overlay یا چت دوم باقی نماند.
- [ ] چت در ناحیهٔ راست Theia و زیر Outline قرار بگیرد؛ آیکون آن با Outline قاطی نشود.
- [ ] ظاهر چت کاملاً از CSS variables تم فعلی Theia استفاده کند.
- [ ] پیام‌های هر کاربر/پروژه/نسخه روی رایانه ذخیره و قابل‌بازیابی باشند.
- [ ] انتخاب مدل رایگان، افزودن فایل/تصویر و انتخاب Skill در Composer داخلی اضافه شود.
- [ ] فعالیت Agent شامل خواندن فایل، جست‌وجو، پیشنهاد تغییر و نتیجهٔ اعمال‌شده به‌شکل رویداد قابل‌فهم نمایش داده شود.
- [ ] دکمهٔ «تصحیح همین اشکال» برای هر Problem و خط قرمز اضافه شود.
- [ ] دکمه با Gradient متحرک اما خوانا نمایش داده شود و فقط هنگام وجود خطا فعال باشد.
- [ ] درخواست AI شامل Prompt پنهان باشد: فقط کد کامل و معتبر همان فایل برگردانده شود؛ بدون سلام، توضیح، Markdown یا متن غیرکد.
- [ ] قبل از جایگزینی فایل، Diff و Snapshot ساخته شود؛ اعمال تغییر فقط پس از تأیید کاربر انجام شود.

## موارد عمداً حذف‌شده از فهرست

- مشکل‌های Explorer ادیتور HTML قدیمی، از جمله دکمه‌های Hover و عرض پنل قدیمی، دیگر هدف این بازسازی نیستند.
- History قدیمی به‌عنوان بخش عمومی ادیتور بازگردانده نمی‌شود؛ Snapshot امنِ AI فقط برای بازگشت از تغییر پیشنهادی استفاده خواهد شد.
